## 0. 结论（先看这五句）

1. **能做，且不需要新增 op 原语**：三层记忆 = `memory.write` 加 `tier` 字段 + 两个读通道（room 级 / world 级），不是新玩法。
2. **分用户 = 账号隔离**（谁的私忆谁看得见）。**世界只有一条**：`worldId` 已是房间上的既有字段（`packages/shared/src/contract/types.ts:97-98`，语义是「同 worldId 共享世界观，但状态不共享」）。本方案新增：**永久记忆挂 `worldId`，跨房间/跨身份/跨用户只读**——这是「世界记得你」的唯一载体。
3. **换档 = 同一 worldId 下新建房间 + 新 `plr_*` 身份**。短期/长期记忆留在旧房间，不自动迁移；旧身份退役时把「公开的长期记忆」沉淀成永久记忆候选，自动审核后进世界层。**旧身份的私忆不会自动继承给新身份**（否则换身份无意义，且隐私会串）。
4. **写记忆不要单独调一次模型**：记忆放在主回合 JSON 的 `memory[]` 里带回（`docs/prompts/00-world-system.md` 已有该字段），引擎侧加校验闸门。单独调一次 = 每回合 +40~60% 成本，省的钱全吐回去。
5. **「只读世界观 + 记忆」能省钱，但省的是「不塞全史」这笔账，不是凭空省。** 相对每回合塞 10 回合原文约省 15~20%，相对 20 回合约省 45%；相对当前 M0 极简提示词（`packages/engine/src/turn.prompt.ts` 只有约 200 token）反而贵 5~8 倍——那是 M3 可玩性应付的钱。三条铁律：缓存前缀稳定、单回合 1 次调用、输出 ≤900。

## 2. 三层记忆定义

| 层 | 名字 | 存什么 | 作用域 / 生命周期 | 进 prompt | 预算 |
|---|---|---|---|---|---|
| 短期 | `short` | 本场对话最近 3 回合的**压缩摘要**（不是原文），含未兑现的话头/情绪 | `(roomId, userId, ownerId)`；会话结束或游戏日切换即清 | 每回合注入 | ≤200 tok |
| 长期 | `long` | 带标签的情节记忆 + 压缩后的印象（impression） | `(roomId, userId, ownerId)`；300 条/owner 上限，按分数淘汰归档 | top-k 检索 | ≤700 tok |
| 永久 | `permanent` | **世界史**：公开事件、校史、已定稿的公共结论、**过往玩家身份的公开事迹** | `worldId` 级，所有房间/所有用户只读；不过期（只允许 tombstone） | 每回合强制注入 top-8（按地点/标签过滤） | ≤200 tok |

**关键边界（要写进 03 的语义）**：

- `short`/`long` 的 `ownerId` 必须是实体（`npc_*` / `plr_*`），读取受 `(userId, roomId, ownerId)` 三重过滤。
- `permanent` 的 `ownerId` 固定为保留 id **`mem_world`**（待入 03 §0.3），**不是实体**、不参与 `live()` 校验；`worldId` 由房间继承；`visibility` 强制 `public`。
- 永久记忆**可以**出现 `plr_*`，但只允许是**已归档身份**（旧档角色）的**公开事迹**；**不得**包含当前在线身份的私密信息、秘密原文、未 resolved 的 plot 内容。硬闸门，不靠提示词自觉。
- 永久条目带 `status: "current" | "historical"`：旧身份事迹统一 `historical`，玩家进入新档时世界观提示里可以出现，但不与该玩家当前身份做「你」指代（防止身份混淆）。

## 3. 分用户存储（用户库）

### 3.1 三个维度，不要混

- **`userId`（账号）**：坐在键盘前的人；多租户隔离键，由 `apps/server` 的登录态提供。
- **`identityId`（身份）**：当前档的 `plr_*` 实体；一个 `userId` 在一条世界线里同时只有一个活跃身份。
- **`ownerId`（视角）**：谁的记忆。NPC 对玩家的印象 = `(ownerId=npc, about=[plr_x], userId=<玩家账号>)`。

同房间两个玩家 A/B 谈同一个 NPC：NPC 的私忆按 `(userId)` 过滤，A 的私事不会在 B 的回合被召回；但 NPC 的「世界观级公开结论」是共享的。

### 3.2 存储分三块

| 层 | 位置 | 性质 |
|---|---|---|
| 权威（房间） | `data/rooms/<roomId>/events.jsonl`（`memory.written` 事件，payload 增加 `userId/tier/contentHash/worldId`） | 唯一真源，可回放 |
| 权威（世界） | `data/worlds/<worldId>/events.jsonl`（专用房间 `room_world_<worldId>` 的事件日志） | 永久记忆的唯一真源，仍由 `Arbiter.apply` 写 |
| 投影 | `data/users/<userId>/mem_index.jsonl`（按 `user_id,room_id,owner_id,tier` 索引，正文只读副本）；`data/users/<userId>/profile.json`（`MemoryProfile` + 已读印象） | 可 `rebuild(events)` 重建；损坏不影响回合 |

> **为什么世界层也用「房间」**：`room_world_<worldId>` 是一个不可玩的保留房间，复用现有 `EventSourcedStore`/`Arbiter`/回放/seq 机制，**不新增存储驱动、不新增 op**。`mem_world` 不是实体，落库时由 `arbiter.ops.ts` 特判（见 08）。

### 3.3 整体世界观 / 换档语义（v1 的「跨存档」问题已定）

**已定（m00046）**：世界是整体的；换档 = 玩家以新身份加入同一世界；世界保留对之前玩家的永久记忆。

落地规则：

1. `short`/`long`：`crossSave=false`（按 `roomId` 隔离）。换档后新身份不会「天生认识」NPC；NPC 对旧身份的印象留在旧房间，不自动搬过来。
2. `permanent`：`scope="world"`，跨房间、跨身份、跨用户只读。旧玩家做过的公开大事，新档里 NPC/校史仍会提到。
3. **身份退役沉淀**：旧房间标记 `retired` 时跑 `canonize.retire(roomId)` 后台作业：
   - 扫描该房间已提交事件里 `broadcast:true` 且能追溯到 `evt_*` 的公开事件；
   - 把相关 `long` 记忆压成候选条目（规则模板 + 摘要，不调叙事模型）；
   - 走 §6.2 自动审核 → 通过写 `room_world_<worldId>` 的永久记忆；
   - 不通过的候选随房间归档（默认保留存档文件，可 tombstone，不物理删）。
4. 世界层只存「公开事实」，不存旧身份的心理活动；旧身份如果删号，永久条目里的 `plr_*` 只保留公开事迹描述，不保留账号关联（`userId` 置空，保 `sourceRefs`）。

> 为什么不迁移 `long`：迁移 = NPC 对新身份「未卜先知」，既毁沉浸感，也把旧身份私忆泄漏给新身份。世界记得的是「事」，不是「你脑子里的事」。

### 3.4 对话前懒查询 + 懒创建（用户要的「先查库」）

```ts
// Dialogue.open(userId, npcId) 前，引擎调用；纯读投影/世界层，不产生事件
const p = await mem.profile(userId, npcId);                       // MemoryProfile | null
const roomHits = await mem.recall({ userId, roomId, ownerId: npcId,
                                    tiers: ["long", "short"], tags: sceneTags,
                                    budgetTokens: 900, nowTurn });
const worldHits = await mem.recall({ scope: "world", worldId, userId,
                                     tags: sceneTags, budgetTokens: 200, nowTurn });
if (!p && roomHits.length === 0) {
  // 首次见面：本回合成功后，与其它提案同一批 atomic apply，写一条「种子记忆」
  // 不额外调模型，内容由规则拼装（NPC 名 + 玩家名 + 场景），salience=3
}
```

`MemoryProfile`（待入 03 §2.6）是**派生投影**，不是世界状态：`{ userId, roomId, ownerId, firstMetTurn, familiarity, impressionIds, lastTopics, seenImpressionIds }`，全部能从记忆行/事件算出来。因此「没有就新建档案」不违反 I1——空档案与不存在等价，不需要 `entity.create` 或新 op。

## 4. 读取：每回合 prompt 怎么拼（省钱的真正位置）

顺序 = 缓存经济性（依据 `docs/v1/开发方案-v1.md` §4.6 预算表）：

```
S1  世界观+硬规则+输出协议    ~1600 tok  静态，逐字节稳定 → 命中缓存
S1.5 永久记忆 top-8            ~200 tok   世界级半静态，按 WORLD_MEM_VERSION 哈希 → 可命中
S4  NPC 卡（去掉 secrets）     ~500 tok   同一 NPC 连续对话命中
S5  场景/时钟                  ~150 tok   动态
S6  数值/关系                  ~250 tok   动态
S7  长期记忆 top-k             ~700 tok   动态（预算硬顶）
S8  短期摘要（替代原文）        ~200 tok   动态
S9  本回合既成事实 + 输入        ~150 tok   动态
```

规则：

- `S7 + S8 + S1.5` 合计硬顶 **1100 tok**；召回先按 `(userId, roomId, ownerId, tier)` 过滤再打分再装箱，超预算按分数降序截断；secret 走 forced 通道，不占预算优先级（沿用 `packages/engine/src/memory.ts` 现有语义）。
- 降级链：长期召回为空 → 用 `profile.lastTopics` 兜底一句；世界层读失败 → 跳过（不重试、不阻塞回合）。
- `S1.5` 变化即 bump `WORLD_MEM_VERSION`（世界层内容的单调版本号，只增不改）；永久记忆**每轮只增不改**，所以前缀几乎不变——这是它便宜的唯一原因。
- 改 S1（含 memory writer 规则）必须 bump `PROMPT_VERSION`；改 S1.5 只 bump `WORLD_MEM_VERSION`。二者不要混。

### 4.1 多 NPC 场景：按 NPC 归属注入（#20 修复）

- 旧实现 `selectOwner`：只有"场景恰好 1 个 NPC"才把 owner 设为该 NPC；多 NPC 时退回玩家 → 两个 NPC 的私忆都不进 S7/S8（#20 根因）。这不是"导演层未接"的临时省略，而是**信息丢失**：模型完全不知道在场 NPC 记得什么。
- 现在 `MemoryContext.npcs` 按 `presentIds` 顺序为每个在场 NPC 分别召回 long/short（ownerId=npcId），注入段按人分段并标名字：`林静（NPC）还记得更早以前的事：…` / `白晓通（NPC）还记得刚才的事：…`。
- 预算：S1.5 先占 ≤200，剩余 1100 均分给每个 NPC（long:short ≈ 700:200，余数给靠前者），最终仍按总量 1100 硬顶裁剪（先 short 后 long，从最后一个 NPC 开始）。单 NPC 保留旧标题"你（NPC）"以维持字节稳定。
- 0 个 NPC 时保持旧行为（owner=玩家，回忆自己的记忆）。
- 写入：模型 `memory[]` 与"首轮种子"按 owner 各过一遍闸门（每个 NPC 每回合仍 ≤3 条）；同一事件会分别记进每个在场 NPC 的私忆——这是有意的（视角独立），但内容会重复，成本可接受。

### 4.2 最近对话（#21-2）

- 每回合裁决成功后，引擎给每个在场 NPC 追加一条 `short` 工作记忆：`刚才玩家说「…」（≤30 字），<本回合叙事摘要>（≤70 字），<NPC 台词>（≤90 字）`（总 ≤200 字），salience 3、visibility private、about=[玩家]，tier short，tags 含"最近对话"+地点名。它走 `memory.write` Proposal，不是直接写库。
- 叙事与台词**分别**分配预算（PR #24 P2-2）：如果只取拼接文本再统一截 100 字，叙事写满时"明早 8 点见"这类台词会被整段丢掉；现在两者都进工作记忆。
- **滚动替换**（PR #24 P2-1a）：写新条前，先对该 owner 现存的旧工作记忆发 `memory.write`（`status:"tombstoned"`，`supersedes:旧 id`），再写新条；同一批提交时 tombstone 排在写入之前。因此每 owner 只保留最新 1 条工作记忆，活条数量不随回合数增长。
- **配额口径**（PR #24 P2-1b）：工作记忆不参与 G3 去重 / G4 重要度提升 / G6 配额——`sessionCap=30` 只约束**情节记忆**，工作记忆另算且只保留最新 1 条。这样工作记忆既不会先把自己撑满 30 条、也不会在模型写满 3 条时被挤掉。
- 用途：下一回合 S8 有"刚才发生了什么"，模型不必只靠当前输入猜上下文；与长期记忆的压缩摘要互补。
- 已知限制：
  - 最近对话只写"在场 NPC"；不在场的人下一回合出现时没有这段上下文（符合"只有在场者知道"的设定）。
  - 修复前已积累的多条旧工作记忆，会在修复后的第一次写入时被一次性 tombstone（旧条不会回收，只是不再计入配额与注入）。
  - `compact` 目前只把记录标 `archived`、且本 PR 未接线；`archived` 记录仍占 `ownedCount`，即情节记忆配额不会因归档而回收——留给后续 issue（压缩/归档的容量回收）。

## 5. 写入：主回合内一次带回，六道闸门

`turn.parse` 现在丢弃 `memory[]`，要改成解析 → 逐条过闸门 → 产出 `{op:"memory.write", args:{...}}` → 与本回合其它提案同一批 `Arbiter.apply`（默认 atomic；**坏记忆在闸门处丢弃，不拖垮整回合**）。

| # | 闸门 | 规则 | 失败处理 |
|---|---|---|---|
| G1 | 归属 | `ownerId` ∈ 本回合在场者；`about` ⊆ 在场者 ∪ 自己；`userId` = 当前发言玩家 | 丢弃该条 |
| G2 | 形状 | 正文 1~200 字（提示词收紧到 100）；tags ≤4（zod 上限）；salience 1~5 | 截断/丢弃 |
| G3 | 去重 | 与近 20 条同 `(roomId,userId,ownerId,tier)` 记忆字面相似度 >0.8 → 丢弃或合并（`salience+1`） | 合并 |
| G4 | salience 校准 | 取 max(LLM 值, 规则值)：涉及自己利益/秘密/被玩家直接触发 → 下限 4 | 覆盖 |
| G5 | 秘密绑定 | 正文若含某 plot 的 `forbidReveal` 原文 → 改写为 `secretRef` 形式，原文不入库 | 改写入参 |
| G6 | 配额 | 每回合每 owner ≤3 条（工作记忆不计）；每 session 每 owner 情节记忆 ≤30 条（工作记忆另算，只保留最新 1 条）；`archived` 仍计入 30 条（compact 未接线，后续 issue） | 丢弃最旧 |

写入后：`short` 进会话缓冲；每 10 回合或会话结束，把 `short` 压成 1 条 `long`（规则模板，不调模型）；每 20 回合走 `docs/prompts/03-compactor.md`（便宜模型，一次调用，后台 job，不占玩家回合）。

## 6. 永久记忆：世界级只读 + 全自动极严写入

### 6.1 谁能写

| 来源 | 是否可提永久记忆 | 附加条件 |
|---|---|---|
| 回合内 LLM（`cause.type="turn"`） | ❌ 一律 `E_FORBIDDEN` | 提示词明确写「你无权写永久记忆」 |
| 模块 / 导演 | ❌ | 同上 |
| 夜间 tick 规则引擎 | ✅ 只能**提案候选** | 候选进 canonize 队列 |
| `canonize` 作业（**唯一真正写入口**） | ✅ 自动审核通过后写 `room_world_<worldId>` | `cause.type="canonize"`（待入 03 可信来源表） |
| 人工 canon 定稿 | ✅ 直接落库 | 记 `source="canon"`，可绕过抽样但仍要过隐私闸门 |

**用户已定：全自动审核**，不再有「前 100 条人工批准」的阻塞门槛。人工只做事后抽样与撤回（§6.5）。

### 6.2 自动审核八道闸门（比长期记忆严一档）

1. **来源可追溯**：`sourceRefs` 必须指向**已提交**的 `evt_*`（房间事件）或 canon id；空来源直接拒。
2. **公共性**：来源事件 `broadcast:true`（`content/registry/events.json`），或 ≥2 个不相关见证者（`npc.spoke` / `scene.set` 的在场记录可证）；否则拒。
3. **隐私扫描**：正文不得含当前活跃身份的私密信息、秘密原文、未 resolved 的 plot 关键词；旧身份只允许公开事迹。命中 → `E_MEMORY_TAINT`，候选丢弃并记日志。
4. **独立审核**：用**与叙事模型不同**的模型/key 家族做 0/1 判定（沿用 `docs/AGENTS` §4.6 的独立性要求；配置 `GALGAME_CANONIZE_MODEL` / `GALGAME_CANONIZE_BASE_URL`，代码不写模型名）。拒绝即丢弃。
5. **幂等/去重**：`contentHash`（正文 + 标签 + sourceRefs 归一化后 sha256）唯一；同 hash 只允许一个版本，重复候选直接跳过。
6. **体量闸**：每日新永久条目 ≤ `canonize.dailyCap`（默认 200）；单来源 ≤2 条；超限进次日队列，不丢。
7. **不可变**：发布后**禁止 update**；只能 `memory.tombstone`（`E_MEMORY_IMMUTABLE` 拒绝改字；改一个字 = 新条目 + 旧条目 tombstone，需理由 + 审核）。
8. **可回滚**：每条永久记忆带 `status`；tombstone 后全局召回立即停止，世界层 `WORLD_MEM_VERSION` +1（缓存前缀失效，下回合重建）。

### 6.3 读

- 所有用户/所有 NPC 都可读，**只读**；读路径 `Memory.recall({ scope:"world", worldId, tags })`。
- 召回按「当前地点标签 + 在场者标签」过滤 top-8，预算 200 tok；与长期记忆分开装箱（避免挤占）。
- 永久记忆**永不进入** `memory.write` 的常规读写路径；前端不下发完整条目（只下发本回合注入的 `memoryIds` 供调试/成就）。

### 6.4 印象反馈：告诉玩家「你在 ta 心中留下了印象」（成就感）

**触发**：canonize 作业写成功一条 `tier=permanent` 且 `about` 指向某个 `plr_*` 身份时，反查该身份的 `userId`，向 `data/users/<userId>/profile.json` 的待投递队列追加一条 `ImpressionNotice`：

```ts
interface ImpressionNotice {
  id: Id;                 // imp_*
  memoryId: Id;           // mem_*
  userId: Id;
  worldId: Id;
  subjectText: string;    // ≤40 字，来自永久记忆正文的公开事实
  npcId?: Id;             // 谁记住了（可空 = 世界记住了）
  createdAt: number;
  deliveredAt?: number;
  seen?: boolean;
}
```

**投递**：该玩家下一回合 `Turn.run` 组装 facts 时，取**未投递**且未过 TTL 的 notice ≤2 条，追加到 `turn.facts`（`packages/engine/src/turn.ts:210-215` 的 facts 数组），格式：

```
【世界印象】王五把你在图书馆当众认下借书单的事，记进了这个世界。
```

- 只走 `turn.facts`（UI 层既成事实），**不占叙事文本、不额外调模型、不增加输入 token**；
- 投递后写 `deliveredAt`（用户投影，非世界状态，可重建）；重建后按 `memoryId` 去重，最多重复提示一次；
- 每回合最多 2 条；`ttlDays=30` 未上线则丢弃；玩家在新身份下也会收到（成就属于账号，不属于身份）；
- 措辞固定为「世界/ta 记住了你做过的事」，**不**让 NPC 在当前身份面前「认出你」（除非新身份主动去查旧档事迹）。

**成就面板（P4 可选）**：`MemoryProfile.impressions` 计数 + `/api/v1/me` 返回 `impressionCount`，前端做「世界印象」列表。先不做新 op、不加属性。

### 6.5 监控与撤回（自动审核的安全网）

- **每日抽样**：`canonize.sampleRate`（默认 0.05）抽最近条目进人工队列，**不阻塞发布**；人工只做「tombstone / 放行」。
- **举报入口**：玩家可举报某条永久记忆 → 先进 `pendingReview`，tombstone 立即生效（先撤再审）。
- **熔断**：`canonize.enabled=false` 立即停止新写入；已写入的按 tombstone 批量撤回。
- **指标**：每日候选数/通过率/拒绝原因分布/tombstone 数；通过率异常（>95% 或 <10%）告警——前者说明闸门松，后者说明提示词或公共性判定有问题。

## 7. 系统提示词里的「写记忆模块」

新增 `docs/prompts/04-memory-writer.md`，在 `00-world-system.md` 的 S1 段用占位 `{{MEMORY_WRITER_RULES}}` 注入，**必须 bump `PROMPT_VERSION`**（`2026-11-16.1` → `2026-11-17.1`（P0 落盘）→ `2026-11-17.2`（PR #4 复审修提示词缓存顺序时再 bump）），因为 S1 是缓存前缀。

内容要点（四写四不写）：

**写**：① 冲突/承诺/欠人情 ② 被看见/被撞破 ③ 首次见面、身份变化 ④ 拿到具体线索（物证、话语）
**不写**：① 寒暄与环境 ② 重复（近 20 条已覆盖） ③ 自己不在场的事 ④ 别人的秘密原文（只写「他好像在瞒什么」）

硬约束：

- 第一人称、含专名、≤100 字；不确定用「好像/大概」；不编因果。
- 每条带 `about`（主体，≤4 个）、`tags`（≤4）、`salience`（1~5，附校准表：日常 1~2 / 有后果 3 / 涉及自己利益或秘密 4~5）。
- 每回合 ≤3 条；`visibility` 默认 `private`，只有公开事件才 `public`。
- **禁止**输出 `tier:"permanent"` 或 `ownerId:"mem_world"`——越权提案由 G1 直接丢弃，并在提示词里明说「永久记忆由世界归档流程负责，你不写」。
- 输出嵌在既有 JSON 里：`{"memory":[{"about":"npc_x","text":"…","tags":["…"],"salience":3,"visibility":"private"}]}`，不新增顶层字段，保持 `narrative→dialogue→proposals→memory→scene→flags` 顺序。
- 世界层注入（S1.5）用固定句式「这个世界已经知道的事：…」，不写成「你记得」，避免模型把世界史当成 NPC 私忆。

## 8. 成本分析（回答「只读世界观+记忆能省钱吗」）

估算口径：正文 1 中文字 ≈ 1 token；静态前缀按未命中价计、命中按 1/10 折算（以实际计费为准，价格会变）。

| 方案 | 每回合输入 tok | 其中可缓存 | 有效成本（相对值） |
|---|---|---|---|
| A 当前 M0 极简提示词（无记忆） | ~300 | 0 | **1.0x** |
| B 每回合塞 10 回合原文 | ~4,150 | ~1,600 | ~2,710 → **~9x** |
| C 每回合塞 20 回合原文 | ~5,650 | ~1,600 | ~4,210 → **~14x** |
| D 本方案（三层，开缓存） | ~3,750 | ~2,100 | ~2,310 → **~7.7x** |
| E 本方案（没开缓存） | ~3,750 | 0 | ~3,750 → **~12.5x** |

换成省钱的说法：

- **D vs B：省约 15~20%**；**D vs C：省约 45%**。回合越多、历史越长，省得越多——这才是「只读世界观+记忆」的正确收益来源。
- **D vs A：贵 5~8 倍**。当前 M0 提示词只有约 200 token，不是「贵」而是「还不可玩」；M3 的记忆/密谋必须付这笔钱。
- **整体世界观本身不加每回合成本**：世界层只多 200 tok 注入（已计入 D），跨档不需要重放旧档历史。
- **新增的唯一成本在后台**：canonize 作业（每天/每次退役，1 次便宜模型调用处理 ≤40 条候选）+ 审核模型（与叙事模型独立，按候选数计费），摊到每回合 <¥0.001；被 `canonize.dailyCap` 封顶。
- 输出 450~600 tok 是固定成本，省不掉；记忆方案不动输出。

**三条铁律（违反任一条，上述收益归零）**：

1. 静态前缀逐字节稳定 + `PROMPT_VERSION`/`WORLD_MEM_VERSION` 只在真改时 bump；
2. **单回合只调 1 次叙事模型**——记忆在同一个 JSON 里带回，不另开 writer 调用；
3. `max_tokens ≤ 900`，记忆预算 1100 硬顶，压缩/canonize 全走后台 job。

**永久记忆的额外账**：世界层缓存按 `user_id` 隔离（v1 §9.2 要求每玩家固定 `user_id`），跨用户不共享缓存；它便宜是因为每回合只注入 200 tok、且内容几乎不变，不是因为大家共用一份缓存。

2. 世界层跨用户/跨房间可读；`tier=permanent` 条目里搜不到当前活跃身份的私密信息/秘密原文。
3. 首次对话无记忆 → 不报错 → 本回合提交后有一条种子记忆。

9. 印象反馈：canonize 成功 → 该 userId 下回合 facts 出现且只出现一次；第二回合不再出现。
10. 永久条目 update → `E_MEMORY_IMMUTABLE`；tombstone 后下一回合召回消失且 `WORLD_MEM_VERSION` 递增。

## 11. 风险与不做的事

| 风险 | 对策 |
|---|---|
| LLM 编造长期记忆（把猜测写成事实） | G3/G4 + 提示词「不确定用好像」+ 记忆不参与数值裁决（数值只信 registry/Arbiter） |
| 永久记忆污染扩散到所有用户/所有档 | 八道闸门 + 不可变 + 每日抽样 + tombstone 熔断 + 世界层版本失效 |
| 自动审核把隐私写成世界史 | 隐私闸门（活跃身份私密信息一律拒）+ 旧身份仅公开事迹 + 审核模型独立 + 举报先撤后审 |
| 记忆串号 / 隐私泄漏 | 召回在存储层按 `userId` 过滤，不靠 prompt 自觉（沿用 v1 §5.5） |
| 缓存前缀抖动导致成本翻倍 | `MEM_VERSION` / `WORLD_MEM_VERSION` + 永久记忆只增不改 + 改提示词必 bump `PROMPT_VERSION` |
| 世界越滚越大 | `permanentMaxEntries=300` 硬顶 + `historical` 条目按年份归档（只留 top-100 高频引用）+ tombstone |
| 换档后旧身份「阴魂不散」 | 永久条目只写公开事迹、`historical` 标记、不关联账号；新身份不继承旧私忆 |

**不做**（明确排除，避免过度设计）：

- 不新增 op 原语；不加向量库（v1 §5.6 触发条件未到：单 owner 活跃记忆 >2000 条 / 召回失败率 >15% / 需要跨语言近义召回）。
- 不做「记忆写入单独一次 LLM 调用」；不做每回合压缩。
- 不让回合 LLM 直接写 canon / 永久记忆原句（只进 canonize 候选）。
- 不为「世界持久化」合并房间状态：世界层只共享记忆，房间状态仍隔离（沿用既有 `worldId` 语义，改动最小）。
- 不做「前 100 条人工阻塞」：已定全自动，人工只做事后抽样/撤回。
