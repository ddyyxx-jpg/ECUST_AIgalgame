# 02 · 数据格式

> 本文解决的问题：**「世界状态长什么样、能写成什么样、存到哪」**。
> 03 号文档定义「接口叫什么名字」，本文定义「数据长什么形状、什么值合法、存在哪张表」。
> 两者的分工：**名字看 03，形状看本文**。JSON Schema 落在 `docs/schemas/v2/`，是从本文 + 03 产出的**机器可校验副本**，冲突时以本文为准（本文是 prose 真源，代码里以 zod 为真源，见 §8）。

阅读顺序建议：§1 三档 → §2 属性注册表 → §3 实体 → §4 十二个原语 → §5 事件 → §6 存储 → §7 迁移。

## 1. 三档数据（canon / soft / x 区）

| 档位 | 落点 | 谁写 | 是否进存档 | 是否进 canon | 校验强度 |
|---|---|---|---|---|---|
| **canon** | `content/canon/**`（只读加载） | 人类（git） | 加载进内存 | 是 | 全字段严格校验 |
| **soft** | `Entity` 正式字段 + registry 声明的 attrs | 引擎承接 AI/模块提案 | 是 | 否（`canon=false`） | 按 registry 校验 |
| **x 区** | `Entity.attrs["x.*"]` | 同上 | 是 | 否 | **不校验类型**，只限数量 |

三句话：
- canon 是宪法，AI 只读；改了要人提交，且 `entity.update` 对 `canon=true` 一律 `E_CANON_LOCKED`。
- soft 是判例，AI 可以造（有配额），但一旦写入，**所有后续推演都要尊重它**。
- x 区是便签，`x.mood`、`x.trace` 这类临时状态写这里，**永不进 canon、不参与数值结算**。

`origin` 字段只有三个值：`seed`（canon 加载） / `ai`（AI 推演） / `system`（引擎内部，如时钟实体）。**没有 `human`**——人类写的东西一律经 canon 加载为 `seed`。

### 1.1 配额（引擎统一执行）

| 对象 | 每房间上限 | 超出错误码 |
|---|---|---|
| soft NPC（`origin=ai`, `kind=npc`） | 24 | `E_QUOTA_EXCEEDED` |
| soft 地点 | 40 | `E_QUOTA_EXCEEDED` |
| 物品 | 200 | `E_QUOTA_EXCEEDED` |
| 传闻（`kind=lore`） | 每夜新增 12 | `E_QUOTA_EXCEEDED` |
| active 剧情线（`plot`） | 6 | `E_QUOTA_EXCEEDED` |
| x 写入 | 每回合 8 条 / 单实体 32 key | `E_X_LIMIT` |
| 单条 `presentIds` / `tags` | 16 项 | `E_OVER_LIMIT`（截断） |

## 2. 属性注册表 `content/registry/attrs.json`

**这是「不改引擎加属性」的唯一入口**：新属性 = 这里加一条 + 前端读 `display` 自动渲染，引擎代码零改动（不变量 I2）。

```json
{
  "schemaVersion": 2,
  "attrs": [ { "key": "stamina", "type": "number", "scope": ["plr"], ... } ]
}
```

### 2.1 `AttrDef` 字段表

| 字段 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `key` | string | ✅ | — | 全局唯一，`[a-z][a-z0-9_]*`；**不得 `x.` 开头** |
| `type` | `number`\|`string`\|`boolean`\|`enum` | ✅ | — | number 可 `attr.delta`；其余只能 `attr.set` |
| `scope` | EntityKind[] | ✅ | — | 允许持有者：`plr/npc/loc/item/fact/lore/plot` |
| `min` / `max` | number | — | 无 | 仅 number 生效；delta 结果**由 Arbiter clamp**，模块不许自己 clamp |
| `default` | number\|string\|boolean | — | 无 | `entity.create` 未给该 attr 时的取值 |
| `values` | string[] | enum 必填 | — | 封闭取值集；写入集合外 → `E_OUT_OF_RANGE` |
| `visibility` | `public`\|`self`\|`secret` | — | `public` | 见 §2.2 |
| `maxDeltaPerTurn` | number ≥0 | — | `20` | 单回合同实体同 key 的 delta 累计上限；超出记 `clamped` |
| `display` | `{label, order?, unit?, style?}` | (public/self 必填 label) | — | 前端面板靠它渲染；`label` ≤12 字 |
| `desc` | string | — | — | 给自己和 AI 看的一句话说明 |

### 2.2 `visibility` 三档（对 UI 与 AI 的影响）

| 值 | 进 UI 面板 | 进叙事/提示词 | 典型用途 |
|---|---|---|---|
| `public` | ✅ | ✅ | 体力、金钱、好感度、声望 |
| `self` | 仅本人可见 | 仅本人相关上下文 | 零钱、私人日记相关数值 |
| `secret` | ❌ | ❌（只通过行为表现得） | guard（戒备）、恐惧、欠债 |

**注意**：`secret` 不等于「AI 看不到」——它仍会以**行为线索**（分档表现）进入叙事，但值本身不进 prompt。这是密谋玩法能成立的前提（见 04 §7）。

### 2.4 加一个属性的 checklist

1. 定 `key`（单数名词、`[a-z0-9_]`、不与保留 ns 冲突）→
2. 定 `type` + `scope`（**先问：真的需要新属性吗？能不能用 `x.*`？**）→
3. 定 `min/max/default/maxDeltaPerTurn`（没有上限的数值属性是事故源）→
4. 定 `visibility`（默认 `public`；`secret` 要写清「靠什么行为表现得」）→
5. 定 `display.label`（≤12 字，中文）→
6. 加进 `attrs.json` → 跑 `npm run check:contract`（zod ↔ JSON Schema 双向比对）→
7. **不要改引擎任何代码**；前端面板自动出现该属性。

## 3. 实体模型 `Entity`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | ✅ | `<kind>_<slug>`，见 03 §0.3；**永不复用**（tombstone 后也不复用） |
| `kind` | EntityKind | ✅ | `plr`/`npc`/`loc`/`item`/`fact`/`lore`/`plot` |
| `name` | string | ✅ | 显示名，≤24 字；重名时引擎加后缀并记 `x.name_collision` |
| `attrs` | Record<string, AttrValue> | ✅ | key 必须在 registry 或 `x.` 区，否则 `E_ATTR_UNKNOWN` |
| `tags` | string[] | — | ≤16 项，检索用；**不是**记忆标签 |
| `origin` | `seed`\|`ai`\|`system` | ✅ | 见 §1 |
| `canon` | boolean | ✅ | true 时只读（`E_CANON_LOCKED`） |
| `status` | `active`\|`dormant`\|`tombstoned` | ✅ | 生命周期，见 §6.4 |
| `createdAt` / `updatedAt` | number | ✅ | 游戏回合序号（不是时间戳） |

### 3.1.5 成员表怎么来（P2）

`RoomState.members` 由 `room.member.joined` 事件投影（payload `{member: RoomMember}`），`room.member.left` 移除。
建房时玩家入房就是一次 `room.member.joined`——**单人房不是特例**，只是成员列表长度为 1。
`RoomMember.userId` 是账号维度在房间里的落点：`MemoryRecord.userId` 由它（或请求体）产生，私忆隔离以此为准。

### 3.2 配套类型（此前 03 只有名字，这里给形状）

```ts
interface Link {                      // 关系边，唯一表达"谁认识谁/谁在哪"
  id: string;                         // link_xxx
  from: string; to: string;           // 两端 entityId
  kind: LinkKind;                     // knows | owes | holds | present | located_in | member_of
  attrs?: Record<string, AttrValue>;   // 如 owes: {amount: 20}
  since: number;                      // 游戏回合
}

type LinkKind = "knows" | "owes" | "holds" | "present" | "located_in" | "member_of";

interface RoomState {
  id: string;                         // room_xxx
  mode: "solo" | "coop" | "pvp";
  ownerId: string;
  members: RoomMember[];              // 长度 1 = solo，禁止 if (mode === "solo")
  inviteCode?: string;
  createdAt: number;
  lastActiveAt: number;
  maxActors: number;
}

interface RoomMember { actorId: string; role: "owner" | "player" | "observer"; joinedAt: number; online: boolean }

interface SceneState { locationId: string; presentIds: string[]; mood?: string }   // mood 只影响叙事语气

interface GameClock { day: number; phase: Phase; turn: number; actionsLeft: number }
type Phase = "morning" | "forenoon" | "noon" | "afternoon" | "evening" | "night";
```

> **`present` 边 vs `SceneState.presentIds` 的权威性**：以 **`scene.set` 产生的 `SceneState.presentIds` 为准**；`present` 边是它的投影，由引擎在 `scene.set` / `move.to` 后自动重建，模块**不得**直接 `link.create(kind="present")`，否则报 `E_ILLEGAL_OP`。

## 4. 十二个 Op 原语的数据格式

> 闭集，新增 = bump `apiVersion`（03 §3）。**默认 atomic：一次 `apply` 要么全成功、要么全回滚**。任何一条被拒 → 整批不落库，`ApplyResult.rejected[]` 逐条给出原因（可追溯到 proposal）；只有调用方显式传 `mode: partial` 时才「坏条目丢弃、余下照做」。
> 限额是**整回合累计**（按 `Envelope.causedBy` 归集），不是按单条或按单次 apply；被拒的整批不消耗额度。

| # | op | args | 关键校验 | 产出事件 | 拒绝码 |
|---|---|---|---|---|---|
| 1 | `attr.delta` | `{entityId, key, delta}` | registry 存在且 `type=number`；`maxDeltaPerTurn`；clamp | `attr.changed` | `E_ATTR_UNKNOWN` `E_ENTITY_MISSING` `E_OUT_OF_RANGE` |
| 2 | `attr.set` | `{entityId, key, value}` | 类型匹配；enum 在 `values` 内 | `attr.changed` | `E_ATTR_UNKNOWN` `E_OUT_OF_RANGE` |
| 3 | `entity.create` | `{entity: EntityDraft}` | id 未占用、配额、kind 合法、`canon=false` | `entity.created` | `E_ID_TAKEN` `E_QUOTA_EXCEEDED` `E_CANON_LOCKED` |
| 4 | `entity.update` | `{entityId, patch}` | `canon=false`；不可改 `id/createdAt/origin` | `entity.updated` | `E_CANON_LOCKED` `E_ENTITY_MISSING` |
| 5 | `entity.tombstone` | `{entityId, reason}` | 引用完整性（§6.4）；`canon=false` | `entity.tombstoned` | `E_CANON_LOCKED` `E_REF_IN_USE` |
| 6 | `link.create` | `{from, to, kind, attrs?}` | 两端存在；不自环；`present` 边禁手建 | `link.created` | `E_ENTITY_MISSING` `E_ILLEGAL_OP` |
| 7 | `link.remove` | `{from, to, kind}` | 边存在；canon 边只读 | `link.removed` | `E_ENTITY_MISSING` `E_CANON_LOCKED` |
| 8 | `move.to` | `{entityId, locationId, via?}` | 邻接校验；同一 locationId 幂等 | `actor.moved` | `E_NOT_ADJACENT` `E_ENTITY_MISSING` |
| 9 | `time.advance` | `{cost}` | 仅引擎/tick 可发；`none/minor/major` | `clock.advanced` | `E_ILLEGAL_OP` |
| 10 | `scene.set` | `{locationId?, presentIds?, mood?}` | 场景存在；presentIds 全部存在且 ≤16 | `scene.changed` | `E_ENTITY_MISSING` `E_OVER_LIMIT` |
| 11 | `memory.write` | `{ownerId, content, tags?, salience?, visibility?, about?, tier?, userId?, worldId?, sourceRefs?, contentHash?, status?, supersedes?, aboutUserIds?}` | 形状见 §4.4；`tier=permanent` 见 §4.4.1 特判 | `memory.written` / `memory.tombstoned` | `E_FORBIDDEN` `E_OVER_LIMIT` `E_MEMORY_TAINT` `E_MEMORY_IMMUTABLE` `E_MEMORY_WORLD_MISMATCH` |
| 12 | `plot.upsert` | `{plot: PlotDraft}` | active ≤6；actors 存在；`forbidReveal` 非空 | `plot.upserted` | `E_QUOTA_EXCEEDED` `E_ENTITY_MISSING` |

### 4.1 `attr.delta`（最常用）

```json
{ "op": "attr.delta",
  "args": { "entityId": "npc_zhang_san", "key": "guard", "delta": 15 },
  "reason": "王五在走廊把他叫住，他起疑", "by": "npc.plot" }
```

效果：`guard: 41 → 56`（未超 `maxDeltaPerTurn:25`，未触 min/max）；产出 `attr.changed{entityId, key, from:41, to:56, clamped:false}`。
若同回合再提 `delta: 20` → 累计 35 超上限 → 只加 25，`clamped: true`，**不报错**。

### 4.2 `entity.create`（AI 造 NPC）

```json
{ "op": "entity.create",
  "args": { "entity": {
    "id": "npc_library_aunt", "kind": "npc", "name": "图书馆管理员周姨",
    "attrs": { "stamina": 70, "intellect": 3, "trust": 5, "guard": 20, "x.temper": "刀子嘴豆腐心" },
```

### 4.4 `MemoryDraft`（`memory.write` 的参数）

```ts
interface MemoryDraft {
  ownerId: string;              // 谁的记忆（ActorId；世界层固定 "mem_world"）
  content: string;              // 1~200 字（引擎再截 500），第一人称、含具体细节
  tags?: string[];              // ≤4 个写入闸门（zod 上限），每个 ≤32 字
  salience?: number;            // 1~5，缺省 3（校准表：日常 1~2 / 有后果 3 / 涉及利益秘密 4~5）
  visibility?: "public" | "private" | "secret";
  about?: string[];             // 主体 entityId（≤8）
  tier?: "short" | "long" | "permanent";   // 缺省 short；turn 只允许 short/long
  userId?: string;              // 账号维度（私忆隔离）；缺省由引擎按房间成员推
  worldId?: string;             // permanent 必填
  sourceRefs?: string[];        // permanent 必填：已提交 evt_* / canon id（≤8）
  contentHash?: string;         // permanent 幂等键（≤64）
  status?: "current" | "historical" | "tombstoned";
  supersedes?: string;          // tombstone/替换旧条目时必填
  aboutUserIds?: string[];      // 反查印象（≤8）
}
```

**存储形状**（`MemoryRecord`，由 `memory.written` 事件投影得到，唯一真源是事件日志）：

```ts
interface MemoryRecord {
  id: string;                   // mem_<contentHash12> 或 mem_<roomId>_<tick>_<seqInTurn>
  roomId: string;               // 世界层 = room_world_<worldId>
  worldId?: string;             // permanent 必填
  userId?: string;
  ownerId: string;              // permanent 固定 "mem_world"（不是实体）
  content: string;
  tags: string[];
  salience: number;             // 1~5
  about: string[];
  aboutUserIds?: string[];
  visibility: "public" | "private" | "secret";
  tier: "short" | "long" | "permanent";
  sourceRefs?: string[];
  contentHash?: string;
  status?: "current" | "historical" | "tombstoned";
  turn: number;
  createdAt: number;
  archived?: boolean;
}
```

#### 4.4.1 `tier=permanent` 的合法性（由 `arbiter.ops.ts` 判，zod 只管形状）

- `ownerId === "mem_world"`（非实体，跳过实体存在性校验）；
- `visibility === "public"`；
- `cause.type === "canonize"`（或 `"canon"`）；
- 写在 `room_world_<worldId>` 房间，且 `room.worldId` 与参数 `worldId` 一致，否则 `E_MEMORY_WORLD_MISMATCH`；
- `status="tombstoned"` 必须带 `supersedes`，且只能 tombstone 同世界层已有条目；**禁止改写正文**（改字 = 新条目 + tombstone 旧条目），否则 `E_MEMORY_IMMUTABLE`。

#### 4.4.2 回合内写入的六道闸门（`packages/engine/src/memory.gate.ts`，纯函数）

| # | 规则 | 失败 |
|---|---|---|
| G1 | `ownerId` ∈ 本回合在场者（`scene.presentIds`）；`about` ⊆ 在场者 ∪ 自己 | 丢 |
| G2 | 正文 1~200 字、tags ≤4、salience 1~5、`tier` ∈ {short,long} | 截断 / 丢 |
| G3 | 与近 20 条同 `(roomId,userId,ownerId,tier)` 的记忆 trigram Jaccard > 0.8 → 合并（旧条 salience+1）或丢新条 | 合并 |
| G4 | `salience = max(LLM 值, 规则下限)`：`about` 含玩家 / `visibility=public` → 下限 4 | 覆盖 |
| G5 | 正文含本房间任一 `plot.forbidReveal` 子串 → 改写为「关于 `{plot.id}` 的事，不能明说」并置 `visibility=secret`；非可信来源则丢 | 改写 / 丢 |
| G6 | 每回合每 owner ≤3；每 session ≤30 | 丢最旧 |

#### 4.4.3 记忆 id 生成（修 `mem_<owner>_<tick>_<tags.length>` 撞 id 的既有 bug）

1. 有 `contentHash` → `mem_<contentHash 前 12 位>`（永久层幂等键，重复写直接跳过）；
2. 否则 → `mem_<roomId>_<tick>_<seqInTurn>`，`seqInTurn` 是本批提案里的序号。

同一回合、同一 owner、同 tags 的两条记忆 id 必须不同（回归测试锁住）。

#### 4.4.4 模型侧的 `memory[]`（P1） 见下；世界层的写入规则见 §4.4.5。

回合输出里的记忆是"草稿"，不是 op 参数：

| 字段 | 必填 | 约束 |
|---|---|---|
| `content` | ✅ | 1~200 字（第一人称视角的一句话） |
| `tags` | — | ≤4 个，每个 ≤32 字 |
| `salience` | — | 1~5（关于玩家的、public 的会被闸门抬到 ≥4） |
| `about` | — | ≤8 个 actorId，必须都在场 |
| `visibility` | — | `public/private/secret`；**叙事层写 secret 一律丢弃** |
| `tier` | — | 只允许 `short/long`；`permanent` 只由 canonize 产 |

`ownerId` 由引擎决定（当前对谈的 NPC），模型自填无效。`contentHash` 由引擎算（sha256 前 32 位），
闸门用它做同回合/跨回合去重与永久层幂等。

#### 4.4.5 世界层永久记忆的写入规则（P3）

> **口径以 `docs/08-引擎改动要求-记忆模块.md` 为准**（owner 决定）：两处冲突时改本文而不是改 08。
> 本文只负责"数据形状"，闸门顺序/配额/审核流程归 08 §7，本 PR 已按其校正。

世界层不是"另一个数据库"，而是**同一份事件日志里另一个房间**：`room_world_<worldId>`（无成员、不可进入、只存 `permanent`）。
候选从房间里的 `public + long` 记忆聚合（同一句话被 ≥`minWitness` 个不同 owner 记住才算公共知识），
然后依次过八道闸门（`packages/engine/src/canonize.ts`）：

| # | 闸门 | 失败表现 |
|---|---|---|
| 1 | 来源可追溯（`sourceRefs` 都是 `evt_/canon_/fact_/lore_/mem_`） | `source_untraceable` |
| 2 | 公共性（不同见证者 ≥2） | `not_public_enough` |
| 3 | 隐私扫描（活跃 `plot.forbidReveal`、secret 记忆原文） | `privacy:plot:<id>` / `privacy:secret_memory` |
| 4 | 独立审核（`CanonizeJudge`，未配置/抛错=拒绝） | `judge:<reason>` / `judge_unavailable` |
| 5 | 幂等（世界层 `contentHash` 唯一） | `duplicate` |
| 6 | 体量（每日 ≤`dailyCap`、单来源 ≤2） | `daily_cap` / `per_source_cap` |
| 7 | 不可变（发布后禁止改字，只能新条目 + `supersedes`） | `E_MEMORY_IMMUTABLE` |
| 8 | 回滚（tombstone 立即生效，`WORLD_MEM_VERSION` +1，下回合缓存前缀重建） | — |

写入唯一路径：`worldArbiter.apply(room_world_<worldId>, [memory.write tier=permanent], cause.type="canonize")`；
房间层与测试都**不能**直接 append 世界层记忆。

#### 4.4.6 世界印象的用户投影（P4）

发布成功 world 层后，"这个世界记住了你"这件事需要告诉**具体账号**，但同一个世界事件对不同玩家投递结果不同
（A 参与的事不该推给 B），所以印象**不是世界状态**，是**用户投影**：

```jsonc
// data/users/<safeUserId>/impressions.json（<safeUserId> 只保留 [A-Za-z0-9_-]，防路径穿越）
{
  "version": 1,
  "userId": "u_a",
  "notices": [
    { "id": "imp_<memoryId>", "memoryId": "mem_...", "userId": "u_a", "worldId": "w1",
      "npcId": "npc_lin", "subjectText": "在校门口帮人捡起散落的书",
      "createdAt": 1770000000000, "deliveredAt": 1770000060000 }
  ]
}
```

| 环节 | 规则 |
|---|---|
| 生成 | canonize 成功后，对候选的 `aboutUserIds`（≤4）各生成一条；`subjectText` 去引号换行、≤40 字、<6 字不生成 |
| 入队 | 按 `memoryId` 去重（同一件事只提示一次） |
| 投递 | Turn 的 facts 追加 `【世界印象】{npcName ?? "这个世界"}记住了你：{subjectText}`，每回合 ≤2 条 |
| 标记 | **只在 `turn.commit` 之后** `markDelivered`（崩在中途宁可下次重复一次，也不要"说过又没说过"） |
| 过期 | `impression.ttlDays`（默认 30）后不再投递，但文件保留（供 `/me` 统计） |
| 容错 | 投递/读文件失败一律降级：本回合没有印象，不影响叙事与落库；坏文件当空处理 |

可见性：`/me` 只返回**自己**的 `impressionCount` 与最近 5 条 `pendingImpressions`；管理员用
`GET /api/v1/admin/stats` 看整体指标与抽样，看不到正文以外的隐私内容。

## 5. 事件与 Envelope

```json
{
  "v": 1, "id": "evt_01J9Z3K4", "roomId": "room_solo01", "seq": 137,
  "ts": 1770000000000, "actorId": "npc_wang_wu", "type": "turn.patch",
  "causedBy": "evt_01J9Z3K3",
  "payload": { "turnId": "turn_01J9Z3K0", "applied": [...], "rejected": [], "seq": 137 }
}
```

规则：
- `seq` **房间内单调递增、无空洞、可续传**；客户端带 `Last-Event-ID` 重连，落后 >200 条 → `E_SEQ_GAP` → `state.sync`。
- `payload` **只增不改**：加字段可以（老客户端忽略），删/改字段 = bump `schemaVersion`。
- 广播范围由 `content/registry/events.json` 声明（全场 / 参与者 / 仅自己），**过滤在 Transport 之前**（04 §6）。

## 6. 存储与投影

**核心原则：表是投影，唯一真源是 `events`。** 任何表都可以 `rebuild(events)` 重建；san 时刻只信事件。

```sql
-- 房间与成员
CREATE TABLE rooms (id TEXT PRIMARY KEY, mode TEXT NOT NULL, owner_id TEXT NOT NULL,
                    invite_code TEXT, max_actors INTEGER NOT NULL DEFAULT 1,
                    created_at INTEGER NOT NULL, last_active_at INTEGER NOT NULL);
CREATE TABLE room_members (room_id TEXT NOT NULL, actor_id TEXT NOT NULL, role TEXT NOT NULL,
                    joined_at INTEGER NOT NULL, online INTEGER NOT NULL DEFAULT 0,
                    PRIMARY KEY (room_id, actor_id));

-- 世界状态投影
CREATE TABLE entities (room_id TEXT NOT NULL, id TEXT NOT NULL, kind TEXT NOT NULL,
                    name TEXT NOT NULL, attrs TEXT NOT NULL,          -- JSON
                    tags TEXT NOT NULL DEFAULT '[]', origin TEXT NOT NULL, canon INTEGER NOT NULL,
                    status TEXT NOT NULL, created_at INTEGER NOT NULL, updated_at INTEGER NOT NULL,
                    PRIMARY KEY (room_id, id));
CREATE INDEX idx_entities_kind ON entities(room_id, kind, status);
CREATE TABLE links (room_id TEXT NOT NULL, id TEXT NOT NULL, from_id TEXT NOT NULL,
                    to_id TEXT NOT NULL, kind TEXT NOT NULL, attrs TEXT DEFAULT '{}', since INTEGER NOT NULL,
                    PRIMARY KEY (room_id, id));
CREATE INDEX idx_links_from ON links(room_id, from_id, kind);
CREATE INDEX idx_links_to   ON links(room_id, to_id, kind);

-- 事件日志（唯一真源）
CREATE TABLE events (room_id TEXT NOT NULL, seq INTEGER NOT NULL, id TEXT NOT NULL,
                    type TEXT NOT NULL, actor_id TEXT NOT NULL, ts INTEGER NOT NULL,
                    caused_by TEXT, payload TEXT NOT NULL,
                    PRIMARY KEY (room_id, seq));
CREATE UNIQUE INDEX idx_events_id ON events(room_id, id);

-- 快照（每 50 回合一份，加速重放）
CREATE TABLE snapshots (room_id TEXT NOT NULL, seq INTEGER NOT NULL,
                    state TEXT NOT NULL,                       -- WorldState JSON
                    PRIMARY KEY (room_id, seq));

-- 记忆（独立于投影，因为量大且检索方式不同）
-- 3.1.0：记忆表是事件日志的投影（可 rebuild），新增 tier/status/user/world 维度
CREATE TABLE memories (id TEXT PRIMARY KEY, room_id TEXT NOT NULL, world_id TEXT,
                    user_id TEXT, owner_id TEXT NOT NULL,
                    about TEXT, content TEXT NOT NULL, tags TEXT NOT NULL,
                    salience INTEGER NOT NULL, visibility TEXT NOT NULL,
                    tier TEXT NOT NULL, status TEXT NOT NULL DEFAULT 'current',
                    source_refs TEXT, content_hash TEXT, about_user_ids TEXT,
                    turn INTEGER NOT NULL, created_at INTEGER NOT NULL, archived INTEGER DEFAULT 0);
CREATE INDEX idx_mem_owner ON memories(room_id, owner_id, tier, turn DESC);
CREATE UNIQUE INDEX idx_mem_hash ON memories(content_hash) WHERE content_hash IS NOT NULL;

-- 回合与模块状态
CREATE TABLE turns (room_id TEXT NOT NULL, turn_id TEXT NOT NULL, client_turn_id TEXT NOT NULL,
                    actor_id TEXT NOT NULL, input TEXT, committed_seq INTEGER, usage TEXT,
                    degraded INTEGER DEFAULT 0, PRIMARY KEY (room_id, turn_id));
CREATE UNIQUE INDEX idx_turns_idem ON turns(room_id, client_turn_id);   -- 幂等
CREATE TABLE module_state (room_id TEXT NOT NULL, module_id TEXT NOT NULL, key TEXT NOT NULL,
                    value TEXT NOT NULL, updated_at INTEGER NOT NULL,
                    PRIMARY KEY (room_id, module_id, key));
```

保留策略：`events` 永久保留（可压缩为段文件）；`snapshots` 只留最近 3 份；`turns` 保留 90 天；`memories` 随实体 tombstone 一起降权不删（§5.4）。

### 6.1 引用完整性（tombstone 前必做）

`entity.tombstone` 被拒（`E_REF_IN_USE`）的情形：在 active plot 的 `actors` 里、是某实体 `parentId`、是玩家当前 `locationId`。
允许删除时：记忆里的引用改记为 `x.tombstoned_ref`（保留文本，人会记得「那个人」）；关系边全部 `link.remove`。

### 6.2 实体状态机

`active` ⇄ `dormant`（30 游戏日无引用）→ 再 30 日 → `tombstoned`（硬删仅限 soft）。canon 实体永不变状态。

### 6.3 地图内容与运行时数据文件

地图数据分两层：**只读内容模板**（进仓库）与**运行时发布/草案库**（落在 `data/`，已被 `.gitignore` 整体忽略，不进存档、可重建）。

| 文件 | 层 | 谁写 | 说明 |
|---|---|---|---|
| `content/modules/map/data/world_map.json` | 内容模板（只读） | 人类维护 | `{schemaVersion:2, worldId, width:6000, height:4500, image, startLocId, scenes[]}`；场景含 `id/name/x/y/status/category/anchorLocId?/desc/tags/links[]/dialogues[]`，`status = built\|under_construction\|planned`，`links[].kind = module\|npc\|dialogue\|scene` |
| `content/modules/map/data/npc-schedules.json` | 内容模板（只读） | 人类维护 | `schedules: Record<npcId, {morning,noon,afternoon,evening,night}>`；5 个 phase 的目标是 `loc` id，缺 phase 或目标非法则该 NPC 本 tick 不动 |
| `data/map/drafts.json` | 运行时（gitignore） | `MapService` | 场景草案库；状态机与字段见 `docs/06-地图模块.md` §5 |
| `data/map/published.json` | 运行时（gitignore） | `MapService` | 已发布用户场景的内容模板；每个房间首次 `travel` 到该场景时懒安装成 `loc` 实体（`origin:"ai"`, `canon:false`） |

- **模板不是状态**：世界状态（`loc` 实体 + `located_in` 边 + `scene.set`）仍只由 `Arbiter.apply` 写进房间事件日志（`data/rooms/*.jsonl`）；地图 JSON 文件不参与回放，删掉也能由事件重建房间状态。
- 坐标写入实体 `attrs.coord_x/coord_y`（registry 已声明，见 §2.3），**不新增 Entity 字段**。
- `published.json` 场景结构见 `docs/06-地图模块.md` §2.3；草案结构见同文 §5；两处字段变更时须同步本文与 `docs/06`。

## 7. 存档与迁移

一份存档 = `manifest.json` + `snapshot-<seq>.json` + `events-<from>-<to>.jsonl` + `memories.jsonl` + `module_state.json`。

```json
{ "schemaVersion": 2, "contractVersion": "3.0.0", "savedAt": 1770000000000,
  "roomId": "room_solo01", "seq": 137, "checksum": "sha256:..." }
```

升级三步（`scripts/migrate.ts --from 2 --to 3`）：
1. 校验 `schemaVersion` 是否支持（不认识的版本直接拒，**不猜**）；
2. 正向应用 `migrations/2→3.ts`（纯函数：旧 WorldState → 新 WorldState，**同时把迁移写成一条 `state.migrated` 事件**）；
3. 跑 `npm run replay -- --verify`，重放到最新 seq，比对 checksum 一致才算成功。

必须 bump major 的改动：删/改事件 payload 字段、删 op、改 Entity 必填字段语义、改错误码含义。**加属性、加事件、加模块、加导演都不需要 bump**。

**3.1.0 记忆迁移说明（读旧档时）**：
- 旧 `memory.written` payload 没有 `tier` → 读成 `short`；没有 `status` → `current`；没有 `userId` → 只能按 `ownerId` 检索（等价于单机档案）。
- 历史上出现过 `visibility: "scene"` 的条目（契约是 `public|private|secret`）→ 读成 `public`，写回时按新值落库；不新增第四种 visibility。
- 旧记忆 id（`mem_<owner>_<tick>_<n>`）不改写：id 是引用键，改写会破坏 `supersedes`/`aboutUserIds` 反查。

## 8. 校验链：zod 是代码真源

```
packages/shared/src/contract/*.ts  (zod schema，手写)
        │  npm run gen:schemas
        ▼
docs/schemas/v2/*.schema.json      (生成物，供外部工具/CI 比对)
        │  scripts/check-contract.ts
        ▼
启动期：加载 attrs.json / manifest / canon → 全量校验，失败则 fail-fast（不许带病启动）
运行期：每个 Proposal → zod.parse → 失败 E_SCHEMA_INVALID（丢弃该条，不断回合）
```

两条纪律：① **不许两处手写同一份结构**（生成而非复制）；② 启动期校验失败 = 进程退出，运行期校验失败 = 单条丢弃。

真实报错文案示例：
- `E_SCHEMA_INVALID: attr.delta.args.delta expected number, received "十五" (proposal#2 by=npc.plot)`
- `E_ATTR_UNKNOWN: key "happiness" 未在 registry 声明且非 x. 前缀 (entityId=npc_zhang_san)`
- `E_QUOTA_EXCEEDED: soft npc 已达 24 上限，拒绝创建 npc_tom`
