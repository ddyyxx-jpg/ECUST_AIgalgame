## 0. 一句话交付定义

把目前**完全没接上的记忆子系统**（`InMemoryMemory` 是死代码：`turn.ts:42` 注入但从不调用，`parseTurn` 丢弃 `memory[]`，`memory.written` 事件不投影、不重建）接成：**回合内写 → 按 `userId` 读 → 世界层永久 → 自动审核 → 印象反馈**，且记忆写失败**永不拖垮玩家回合**。

### 2.1 新类型（`packages/shared/src/contract/types.ts`，放在现有「记忆」段 :555-610）

### 2.2 zod（`packages/shared/src/zod/op.ts:144-160`）

`MemoryWriteArgsSchema` 只增字段，op 名不变：

```ts
tier: z.enum(["short", "long", "permanent"]).optional(),
sourceRefs: z.array(IdSchema).max(8).optional(),
contentHash: z.string().max(64).optional(),
status: z.enum(["current", "historical", "tombstoned"]).optional(),
supersedes: IdSchema.optional(),      // tombstone/替换旧条目用
aboutUserIds: z.array(IdSchema).max(8).optional(),
```

**permanent 的合法性放 `arbiter.ops.ts` 判**（zod 只管形状）：
- `ownerId === "mem_world"`（非实体，跳过 `live()`）；
- `visibility === "public"`；
- `cause.type === "canonize"`（或 `canon`）；
- 写在 `room_world_<worldId>` 房间，`room.worldId` 与参数一致，否则 `E_MEMORY_WORLD_MISMATCH`；
- `status="tombstoned"` 必须带 `supersedes`，且只能 tombstone 同世界层已有条目；禁止改写正文（改字 = 新条目 + tombstone 旧条目，否则 `E_MEMORY_IMMUTABLE`）。

`E_MEMORY_TAINT`（来源/隐私不合格）、`E_MEMORY_IMMUTABLE`（改已发布永久条目）、`E_MEMORY_WORLD_MISMATCH`（世界层房间/版本不匹配）。

## 3. 记忆的事件溯源（核心，先解决「死代码」）

**现状问题**：`memory.written` 事件写进房间日志，但 `InMemoryMemory` 完全不知道（`projection.ts:187-191` 明确不投影）；服务重启即失忆，也无法从事件重建。I1 要求日志是唯一真源，必须补上。

要求：

1. `memory.ts` 改为索引式投影：`ingest(env: Envelope)` 把 `memory.written`/`memory.tombstoned` 事件变成 `MemoryRecord`，内部按 `(roomId, userId, ownerId, tier, tags)` 建 Map 索引；`rebuild(roomId, envelopes)` 清空重建。
2. `Turn.run` 在 `arbiter.apply` 成功后调用 `this.deps.memory.ingest(e)` 逐条喂事件（`applied.events`）；**不要**再让 Turn 直接 `memory.write()`。
3. `apps/server` 启动时对每个已加载房间执行 `memory.rebuild(roomId, await store.events(roomId, 0, Infinity))`；世界房间同理（`room_world_<worldId>`）。
4. `Memory.recall` 支持 `scope:"world"`：查世界房间索引，过滤 `status !== "tombstoned"`，按 tags/地点打分（沿用 0.45/0.25/0.2/0.1 公式），预算装箱，`budgetTokens=200`。
5. `Memory.profile` 纯派生：扫描该 `(userId, roomId, ownerId)` 的 long/short + 世界层 `about` 含该身份/`aboutUserIds` 含该 userId 的 permanent，算 `firstMetTurn/familiarity/lastTopics/impressionIds/impressions`；空档案返回 `null`（**不创建实体、不产事件**，空档案 ≡ 无记录，不违反 I1）。
6. 保留 `write()` 只给测试用；正式写路径唯一：`Proposal → Arbiter → event → ingest`。

**必须修的既有 bug（`arbiter.ops.ts:257-271`）**：

| 行 | 现状 | 改成 |
|---|---|---|
| `:270` | `memoryId = mem_${owner.id}_${tick}_${tags.length}`，同回合同 owner 同 tags 数会撞 id | `mem_${roomId}_${tick}_${seqInTurn}`（`seqInTurn` 由本次 apply 的 proposal 序号给）或 `mem_${contentHash.slice(0,12)}`；单测锁住「同回合两条同 owner 同 tags 不撞 id」 |
| `:268` | `visibility` 只认 `private\|scene\|public`，与 zod `public\|private\|secret` 冲突 | 以 zod 为准：`public\|private\|secret`；`scene` 若历史数据存在，兼容读成 `public` 并记录迁移说明 |
| `:266` | `salience` clamp `0~100`，与 zod 1~5 冲突 | clamp `1~5`，缺省 3（提示词校准表：日常 1~2 / 有后果 3 / 涉及利益秘密 4~5） |
| `:262` | 代写资格 `["engine","tick","dialogue","plot"]` | 加 `"turn"`（且仅限 `tier` 为 short/long）；`secret` 仍只允许 engine/dialogue/plot 骨架写，turn 提 `secret` 直接 `E_FORBIDDEN` |
| 新增 | `permanent` 无特判 | 按 §2.2 特判 `mem_world`、`visibility=public`、`cause=canonize/canon`、世界房间校验 |

## 4. 回合内写记忆（`turn.parse.ts` + `memory.gate.ts` + `turn.ts`）

### 4.1 解析

`parseTurn` 返回值加 `memory?: unknown[]`；在 `turn.ts` 里用 zod 逐条校验 `MemoryWriteArgsSchema`（去掉 `ownerId`，owner 由引擎按 G1 推）——**坏条目直接丢，不抛错、不重问模型**。最多取前 3 条（`memory.writePerTurn`）。

### 4.2 六道闸门（`memory.gate.ts`，纯函数）

输入 `{ state, userId, actorId, drafts, recent: MemoryRecord[], limits }`，输出 `{ accepted: MemoryDraft[], dropped: {index,reason}[] }`：

| # | 规则 | 失败 |
|---|---|---|
| G1 | `ownerId` ∈ 本回合在场者（`state.room.scene.presentIds`）；`about` ⊆ 在场者 ∪ 自己；`userId` 来自 `req.userId` | 丢 |
| G2 | 正文 1~200 字、tags ≤4、salience 1~5、`tier` ∈ {short,long}（turn 不允许 permanent） | 截断/丢 |
| G3 | 与近 20 条同 `(roomId,userId,ownerId,tier)` 的记忆用 **trigram Jaccard** 相似度 >0.8 → 合并（旧条 salience+1）或丢新条；手写实现，**不引依赖** | 合并 |
| G4 | salience = max(LLM 值, 规则下限)：`about` 含玩家/含 secret/`visibility=public` → 下限 4 | 覆盖 |
| G5 | 正文含本房间任一 `plot.forbidReveal` 子串 → 改写为「关于 `{plot.id}` 的事，不能明说」并置 `visibility=secret`（仅 trusted 来源）；否则丢 | 改写/丢 |
| G6 | 每回合每 owner ≤3；每 session ≤30；超 short 容量触发压缩 | 丢最旧 |

### 4.3 两阶段裁决（保证「坏记忆不拖垮回合」）

1. 第一批 `apply([...moduleProposals, ...llmProposals, ...memoryProposals])`。
2. 若 `!ok` 且 `rejected` **全部是 memory 提案**：丢掉这些提案，用同一批叙事提案重试一次 apply（**不重问 LLM、不花第二次模型钱**），并 emit 一条 fact：`记忆写入未通过校验（N 条已忽略）`。
3. 若 `rejected` 含叙事/模块提案：走现有修复/失败路径，记忆不特殊。

> 不允许把记忆放进第二次 LLM 修复请求；不允许记忆失败导致 `turn.error`。

### 4.4 首次见面种子记忆

首轮成功后（`profile === null` 且 long/short 召回为空），用规则拼一条 `long`：`「{npcName} 第一次见到 {playerName}，在 {locName}，{day}日{phase}。」`，`salience=3`，与本回合提案同批 apply。**不调模型、不额外写事件类型**。

## 5. 读取：prompt 装配（`turn.prompt.ts` + `turn.llm.ts` + `turn.ts`）

### 5.1 Turn 侧

在 `DefaultTurn.run` 的 LLM 调用之前：

```ts
const memCtx: PromptMemory = {
  permanent: await memory.recall({ roomId: worldRoomId, scope:"world", worldId, ownerId:"mem_world",
                                    userId, tags: sceneTags, budgetTokens: 200, nowTurn }),
  long:      await memory.recall({ roomId, userId, ownerId: npcId /*或 actorId*/, tiers:["long"],
                                    tags: sceneTags, budgetTokens: 700, nowTurn }),
  short:     await memory.recall({ roomId, userId, ownerId: npcId, tiers:["short"],
                                    tags: sceneTags, budgetTokens: 200, nowTurn }),
  profile:   await memory.profile(userId, npcId, roomId),
};
```

- `npcId` 的取法：当前场景唯一 NPC 或 `req.actorId` 的对谈对象；没有对谈对象时 `ownerId = req.actorId`（玩家自己的记忆）。
- 单回合仍然只调 **1 次**叙事模型；记忆召回是纯本地计算，**不调模型**。
- 记忆读取异常：`try/catch` 后置空，继续回合（降级不阻塞）。

### 5.2 提示词签名

`TurnDeps.buildPrompt` 改为：

```ts
buildPrompt?: (state: WorldState, actorId: ActorId, input: string,
               mem: PromptMemory) => string | Promise<string>;
```

`turn.prompt.ts` 的默认实现按固定顺序拼（**顺序是缓存契约，不许改**）：

```
S1  世界观+硬规则+输出协议       静态，逐字节稳定（server 从 content/canon + docs/prompts 读入）
S1.5【这个世界已经知道的事】       permanent top-8，≤200 tok，按 WORLD_MEM_VERSION 标记
S4  NPC 卡（去 secrets）          ≤500 tok
S5  场景/时钟                     ≤150 tok
S6  数值/关系                     ≤250 tok
S7 【你记得的事】                 long top-k，≤700 tok
S8 【最近发生】                   short 摘要，≤200 tok
S9  本回合既成事实 + 玩家输入      ≤150 tok
```

- `S7+S8+S1.5` 硬顶 **1100 tok**；超预算按分数降序截断，`forced`（secret）优先不占额。
- 估算函数：CJK 按 `chars` 计（保守），统一放 `memory.ts` 导出的 `estimateTokens(s)`；`recall` 的装箱与 prompt 拼装用同一个函数。
- 世界层句式固定为「这个世界已经知道的事：…」，**不写「你记得」**，避免模型把世界史当 NPC 私忆。
- 静态段在前、动态段在后；记忆块内按 `id` 排序保证逐字节稳定（同输入同输出）。
- 改 S1 或 memory-writer 规则 → bump `PROMPT_VERSION`；世界层条目变化 → bump `WORLD_MEM_VERSION`（server 每次 canonize 后重算并持久化）。

## 6. 长期记忆生命周期（`memory.ts` + 后台 job）

1. `short`：每回合写、会话结束（房间 `lastActiveAt` 超时或 `retire`）清空/转 long；容量 ≤ 30 条/owner。
2. 每 10 回合规则压缩：`short` 最近 3 回合 → 1 条 `long`（模板：「{玩家}在{地点}{做了什么}」），不调模型。
3. 每 20 回合走 `docs/prompts/03-compactor.md`（便宜模型，一次调用，后台 job）把 10 条 long 压成 1 条 impression；失败保留下轮重试，**不影响玩家回合**。
4. `long` 每 owner 上限 300 条；超出时 `salience` 最低的 1/3 置 `archived`（保留可检索，不进 prompt）。
5. `compact()` 保留现有签名，内部改为上述规则。

## 7. 世界层永久记忆 + 全自动审核（`canonize.ts`）

### 7.1 世界房间

- 每个 `worldId` 一个保留房间：`room_world_<worldId>`（如 `room_world_canon_main`），`mode:"solo"`、无成员、不可进入。
- `apps/server` 启动时为每个已加载 worldId 初始化 world store + world arbiter（独立的 `EventSourcedStore`/`DefaultArbiter`，同一存储目录）。
- 世界层写入只经 `worldArbiter.apply(room_world_<worldId>, [memory.write tier=permanent ...], cause.type="canonize")`。

### 7.2 候选生成

`CanonizeJob`（新类）两个入口：

```ts
class CanonizeJob {
  constructor(deps: {
    store: EventLog; arbiter: DefaultArbiter;          // 房间
    worldStore: EventLog; worldArbiter: DefaultArbiter;// 世界
    memory: Memory;
    judge: CanonizeJudge;                              // 独立审核模型端口，server 注入
    now?: () => number;
    limits: { dailyCap: number; minWitness: number; enabled: boolean };
  });
  retireRoom(roomId: RoomId): Promise<CanonizeReport>;  // 旧档退役
  runDaily(worldId: Id): Promise<CanonizeReport>;       // 夜间补扫
}
export interface CanonizeJudge {
  review(c: PermanentCandidate): Promise<{ allow: boolean; reason?: string }>;
}
export interface PermanentCandidate {
  worldId: Id; content: string; tags: string[]; about: ActorId[];
  aboutUserIds?: Id[]; sourceRefs: Id[]; status: "current" | "historical";
}
```

候选来源：房间内已提交、`broadcast:true` 的事件（`content/registry/events.json`），聚合出「谁在何时何地做了什么」；`retireRoom` 时额外把该房间 public 的 `long` 记忆压成候选。

`CanonizeJudge` 必须由 `apps/server` 用**与叙事模型不同家族**的模型/key 实现（env `GALGAME_CANONIZE_*`），引擎不读 key、不写模型名。

### 7.3 八道闸门（顺序执行，任一失败丢候选并记日志）

1. 来源可追溯：`sourceRefs` 非空且全部指向已提交 `evt_*`/canon id。
2. 公共性：来源事件 `broadcast:true`，或 ≥2 个不相关见证者（`clock.advanced`/`scene.changed`/`npc.spoke` 的在场记录可作证；`minWitness` 默认 2）。
3. 隐私扫描：正文不得出现当前**活跃身份**的私密信息、`plot.forbidReveal` 原文、`visibility=secret` 记忆原文；旧身份仅允许公开事迹（`status="historical"`）。命中 → `E_MEMORY_TAINT`。
4. 独立审核：`judge.review()` 返回 allow；拒绝即丢。
5. 幂等：`contentHash = sha256(归一化(content)+tags+sourceRefs)` 在世界层唯一；重复跳过。
6. 体量：每日新条目 ≤ `canonize.dailyCap`（默认 200）；单来源 ≤2 条；**当日超限不落库、不单独持久化队列**——候选是房间记忆的纯函数（`contentHash` 聚合 + 原记忆长期有效），跨日后 `dailyCap` 重置会被下一次扫描重新聚合出来，因此"次日再试"不需要额外存储。（v2 修订：原稿写的"持久化未处理候选队列"已删除，理由见 §13 偏差表。）
7. 不可变：发布后禁止 update；改字 = 新条目 + `supersedes` tombstone 旧条目；否则 `E_MEMORY_IMMUTABLE`。
8. 回滚：tombstone 立即生效（`status="tombstoned"`），世界层 `WORLD_MEM_VERSION` +1，下回合缓存前缀重建。

### 7.4 事件

- `memory.written` payload 增加：`tier/userId/worldId/contentHash/sourceRefs/aboutUserIds/status`（只增字段，旧日志可读）。
- 新增 `memory.tombstoned`（payload：`{memoryId, supersedes, reason, at}`）与 `memory.impression.queued`（payload：`{noticeId, memoryId, userId, worldId, subjectText, npcId?}`），写进 `content/registry/events.json`。**新增事件类型不 bump apiVersion**（`docs/03` §0.4）。

## 13. 实施记录与偏差（PR #4 复审后）

> 本节由实现方回填：只记录**与本文件正文不一致**的地方，正文仍是口径来源。

| 项 | 正文要求 | 实际实现 | 原因 |
|---|---|---|---|
| `canonize.sampleRate` | 每日抽样比例 | 改为 `canonize.scanMinutes`（定时补扫）+ `GET /api/v1/admin/stats?sample=N`（按需抽样） | "抽样率"没有落地方式时会变成死键；按需抽样更简单且可测 |
| `canonize.enabled` | 未规定默认 | 默认 **true**（judge 未配置 = `DenyAllJudge` 全拒） | 闸门本身 fail-closed，开着不会写坏数据；关掉只用于"不想跑这条链路" |
| 世界层版本 | `mem.version` 落盘 | 落盘 + **启动读回**（`startVersion`），发布后回写 | 只写不读会让重启后退回 0，幂等与版本号都失去意义 |
| 记忆索引 | `sync` 增量 | 启动时 `rebuild-room` + `rebuild-world`；`store.events` 默认 `limit=Infinity` | 世界房间不进 Turn 的 sync 路径，且 200 条上限会让记忆在中局静默冻结 |
| 私忆 id | `mem_<contentHash>` | `mem_<roomId>_<turnSeq>_<seqInTurn>`（`turnSeq` = 回合信封 seq；哈希只用于永久层） | 同内容不同 owner/房间必须各存一条，内容哈希会撞 id |
| `publish` 可读性 | 单文件 | 拆 `canonize.candidates.ts` / `canonize.types.ts` / `canonize.publish.ts`，`canonize.ts` 208 行 | AGENTS §6 文件 ≤300 行 |
| G6 超限 | 「进次日持久化队列（不丢）」 | **不建队列**：当日 `skip("daily_cap"/"per_source_cap")`，跨日后由下一次扫描重新聚合（`dailyCap` 按日重置） | 候选是房间记忆的纯函数（`contentHash` 聚合），原记忆不会因为当日跳过而消失；单独队列等于把同一份候选存两遍，还会引入"队列与记忆不一致"的新 bug |
| `WORLD_MEM_VERSION` | 每次发布 +1 | 常量 **1**（**记忆格式版本**）；世界内容版本用 `worlds/<worldId>/mem.version` 递增 | 两者语义不同：格式版本只在 S1.5 结构变化时 bump（提示词缓存前缀），内容版本才随发布/撤回递增 |
